# QQ 调课同步 v1.4.1 —— 稳定性加固

> 批量调课之后，把「双源并发、AI 限流、日志排查」这几处生产隐患一次补齐。

## 🛡️ 并发保护

- **补丁器加锁**：`TempClassPlanPatcher` 内部用 `lock` 串行化「批量调课 / 撤销」，即使 QQ 与小橙看班同时来指令也不会并发写档案。
- 现有调用链本来就在 **单轮询循环 + UI 线程** 内串行执行，这把锁是防止未来新增调用路径（其它插件、定时任务）导致档案冲突的**廉价保险**。

## 🚦 AI 请求限流

| 机制 | 说明 |
|---|---|
| 单实例串行 | `SemaphoreSlim(1,1)`，同一时刻只发一个模型请求 |
| 最小间隔 | 两次调用至少间隔 **1.5 秒**，两个来源同时触发时后到者直接回退正则 |
| 429 冷却 | 收到 HTTP 429 后进入 **60 秒冷却**，冷却期内不再发请求（日志：`AI 调用失败（限流）`） |

## 🏷️ 统一日志前缀

所有调课相关日志现在都带 `[调课中枢]`，两个插件共用同一标签，排查时一眼定位：

```bash
# ClassIsland 日志里筛这几个就够
[调课中枢] 收到 QQ Toast
[调课中枢] 解析到 N 条指令（来源：AI / 小橙看班）
[调课中枢] 已为今天创建临时层课表
[调课中枢] 执行调课失败 / AI 调用失败（限流）
```

小橙看班侧的「转发给 QQ 调课同步」「联动已连接」等日志也统一带该前缀。
